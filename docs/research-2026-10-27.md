# ANE research update (2026-10-27)

Read-only research by the coordinator session. Nothing ran on the M3.

## Result

No Linux project runs the ANE on an M3 (H15) or M4. Our own macOS device-tree dump already holds the ANE node, so Stage 1 of the README plan is mostly done on paper.

## Stage 1 data we already have

Source: `private-dumps/macos-final-2026-10-27/adt-full-2026-10-27.txt`, lines 8059 to 8125 (also `private-dumps/m3-adt-full-2026-10-26.txt` from line 8054). `private-dumps/` is git-ignored and stays private.

| Item | Value | Note |
|---|---|---|
| Node | `ane@F8000000` | Six register regions: 32 MB, 96 KB, 16 KB, 144 KB, about 15.5 MB, 16 KB. The `reg` values are parent-relative; check all six before a DT node is written. |
| Interrupt | 0x240 (ANE), 0x241 (its DART), on the AIC | One interrupt on the ANE node. The M2 driver may expect more. |
| Power | `power-gates` 0x1a4, `clock-gates` 0x1a4, `clock-ids` 0x14c, 0x14b, 0x14a | IDs only. Map 0x1a4 to a PMGR domain name before any power-on. |
| IOMMU | `dart-ane@F9800000`, `dart,t8110`, dart-id 0x1d, 16 stream IDs, page size 0x400000, 4 instances | Linked by `iommu-parent`. |
| Firmware | No `firmware-name`. `segment-names "__TEXT;__DATA"`, `pre-loaded = 1`; ioreg says `FirmwareLoaded = Yes` | Suggests iBoot preloads the firmware (not verified). The restore image holds `t603x_ane0_fw_erebus_ls5x.im4p` (1.56 MB, listed in that folder's `SHA256SUMS`). The file stays on the machine. |
| Identity | `ane,t8020` compatible, architecture `h15g`, 16 ANE cores, ANE version 144 | `dumps/ioreg-l.txt` lines 30123 to 30139. Kexts `AppleT6030ANEHAL`, `AppleH11ANEInterface`. |

The coordinator checked lines 8059 to 8104 of the first file on 2026-10-27: `interrupts`, `power-gates`, `iommu-parent` and `pre-loaded` are present as listed.

## What the ANE can add

- Text generation: no gain. It is memory-bound, and the ANE shares the same memory. Community numbers on an M4 Max: Llama 3.2 1B at 47 to 62 tok/s on the ANE against about 204 on the GPU ([source](https://insiderllm.com/guides/apple-neural-engine-llm-inference/)).
- Power: about 2 W on the ANE against about 20 W on the GPU (same source).
- Small fixed-shape models: the Whisper tiny encoder on an M1 took 117 ms on the ANE against 631 ms on the CPU ([whisper.cpp PR 1021](https://github.com/ggml-org/whisper.cpp/pull/1021)).

## Next stages (estimates)

1. Stage 2 (1 to 3 weeks): map power gate 0x1a4 to a PMGR domain, write a `t6030` ANE DT node, and probe it with power-on through genpd only. Needs a test DTB and a reboot window with the user's go.
2. Stage 3 (1 to 3 months or more): adapt the `ane_t6021` firmware boot and mailbox path to H15, using the m1n1 hypervisor to trace macOS. No public H15 protocol exists.
3. Stage 4: run one fp16 matmul hwx compiled offline by Core ML on this Mac in macOS.
